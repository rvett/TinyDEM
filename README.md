## Installation & system requirements

TinyDEM requires a C++ compiler compatible with the C++11 standard and the OpenMP 3.1 specification. No further dependencies apply. To compile it, run

``g++ -fopenmp -O3 -o tinydem tinydem.cpp``

or an equivalent command. Omitting the ``-fopenmp`` option compiles it for serial execution.

## Execution

To run a simulation, set the desired parameters in lines 8-31 of [tinydem.cpp](tinydem.cpp), compile it, and execute the binary by typing

``OMP_NUM_THREADS=8 ./tinydem mesh.off particles.csv output``

or similar. If no number of threads is specified, the selection of a suitable number is delegated to OpenMP. The three command line arguments are optional:
- ``mesh.off``: A text file in the [Object File Format (OFF)](https://en.wikipedia.org/wiki/OFF_(file_format)) specifying the mesh geometry. Points, lines, triangles and rectangles are supported mesh elements. At the end of each face specification in the OFF file, an optional integer index can be specified. While this is intended as a colormap index in the OFF specification, TinyDEM uses it to specify the index in the list of mesh radii ``Rmesh`` (see the supplied default [mesh.off](mesh.off) file). If omitted, this index is set to ``0``, such that the first entry in ``Rmesh`` is the default.
- ``particles.csv``: A comma-separated value file specifying the particles to start the simulation with. The format is identical to the output files generated by TinyDEM itself. For an example, run the default simulation.
- ``output``: Path of the output directory. If unspecified, a folder named ``output`` is generated in the current working directory.

To skip any of these arguments, use an empty string (``""``) for it. For example, to only set a custom output directory but load no mesh or particle file, use:

``./tinydem “” “” custom/output/path``

The default simulation ``./tinydem mesh.off`` spawns 1000 particles that fall in an hourglass with obstructed neck. It completes in about 10 seconds in serial mode on a modern computer.

## Output postprocessing & visualization

TinyDEM produces a time series of minimal CSV files, overwriting existing files without prompt. The number of files written is ``1+Nframes`` where the extra 1 is the initial state. Between frames, ``Nsteps`` timesteps are performed.

The simulated particle ensemble can be visualized in [ParaView](https://www.paraview.org). Open the CSV file series and apply the ``TableToPoints`` filter to it, using the ``x``, ``y`` and ``z`` columns, with the ``Keep All Data Arrays`` option enabled. The particles can then be rendered either using the fast ``Point Gaussian`` representation with the radius ``R`` selected in ``Use Scalar Array``, or using the ``3D Glyphs`` representation with ``Sphere`` as the ``Glyph Type``, ``Magnitude`` as ``Scale Mode`` and ``R`` as the ``Scale Array``. To also apply the quaternion rotation to the rendered particles (for instance to show their orientation with an ``Arrow`` glyph), apply a ``Programmable Filter`` after the ``TableToPoints`` filter with the following Python code:

```
import numpy as np
q = [inputs[0].PointData["q%s"%i] for i in range(4)]
output.PointData.append(np.stack(q, axis=1), "q")
```  

This makes the quaternion ``q`` available as ``Orientation Vectors`` in ParaView's ``3D Glyphs``.

## Changes since original publication

### New functionality
- Analogous to the original spawn region (now named ``source``), a sink region (``sink``) is defined where particles are removed when their center lies inside. Sinks can also be half-spaces by setting ``sink = {{-big,-big,-big}, {big,big,0}}`` for example.

### Improved physics
- The rolling velocity originally used $r^\ast=1/(1/r_i + 1/r_j)$ as lever arm, while the rolling torque used $R^\ast=1/(1/R_i + 1/R_j)$. Which one to use is a modeling choice, but they should be equal for the rolling power to be dissipative exactly. The new implementation uses $r^\ast$, as recommended by Zhao, Luo & Li.[^1] The new rolling torque thus reads $`\tau_\text{r}=r^\ast\thinspace\hat{\mathbf{n}}\times\mathbf{f_\text{r}}`$.
- Originally, the twisting friction coefficient was defined as $\mu_\text{t}=(2/3)\mu_\text{s}$ based on the assumption of a uniform pressure distribution over the contact area.[^2] For spherical particles, however, the distribution is non-uniform, leading to the relationship $\mu_\text{t}=(3\pi/16)\mu_\text{s}$,[^3]$^,$[^4] which is now implemented.
- The twisting resistance stiffness coefficient can be related to sliding. In no-slip twisting for identical materials, $k_\text{t}/k_\text{s}=2(2-\nu)/3$,[^5]$^,$[^6] which is now implemented. For incompressible materials ($\nu=0.5$), this reduces to the previously used equality $k_\text{t}=k_\text{s}$.
- The twisting velocity and the twisting torque both originally used $R^\ast$ rather than the contact area $a$ as lever arm. To correct this, the twisting velocity now reads $`v_\text{t}=a\thinspace\mathbf{\omega}\cdot\hat{\mathbf{n}}`$ and the twisting torque $`\tau_\text{t}=f_\text{t}\thinspace a\thinspace\hat{\mathbf{n}}`$. To prevent unrealistic prolonged twisting oscillations with this new model, the damping coefficient for twisting resistance is set to its critical value, $c_\text{t}=2\sqrt{k_\text{t}I^\ast}/a$, where $I^\ast=1/(1/I_i+1/I_j)$ is the effective moment of inertia.

### Bugfixes
- Quaternion updates were originally carried out in the body frame. For correct visualization of particle orientation, the updates are now done in the lab frame using left Hamilton products instead of right Hamilton products.
- Contact data lookup is guarded by a critical section in particle-mesh collisions to avoid a race condition when a particle is in simultaneous contact with multiple mesh faces.

### Robustness & compatibility improvements
- Blank or truncated lines in the input CSV file no longer produce a particle with stale values from the previous row
- The mesh and ensemble file readers no longer lead to hangups when invalid file paths are specified
- Additional range and stream checks for a more robust mesh constructor
- Portable definition of $\pi$ compatible with ``float``, ``double``, and ``long double``
- Better support of ``-ffast-math`` and ``-ffinite-math-only`` compile options
- Complete list of ``#include``s without relying on compilers' transitive inclusions
- Stricter type safety through the use of ``std::ptrdiff_t``; compiling with ``-Wconversion`` and ``-Wsign-conversion`` no longer issues warnings

### Code improvements
- New functions such as ``friction()``, ``Box::contains()``, ``Quaternion::left_mult_exp()``, ``Ensemble::first()``, ``Ensemble::for_nearby()``, and various lambdas to reduce code redundancy
- Shorter implementation of ``rectangle_point()`` using ``edge_point()``
- Replaced the parameter for the number of particle spawn attempts per timestep (``Nspawn``) by a more natural, step size-independent particle spawn rate (``rate``), such that ``Nspawn = rate * dt``
- Create the output directory only once in ``main()`` to avoid spawning a shell for every output frame
- Shorter signature of the ``collision()`` routine via pseudo-particles for mesh elements (which also makes the code easier to extend to moving meshes)
- Extended const correctness
- Faster vector operations by avoiding OpenMP atomic updates where they are unnecessary
- Various small changes (comments, layout, a few renames, etc.)
